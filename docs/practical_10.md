# Практическая работа №10

## Административная панель Django и работа с данными через ORM

Проект: система учета партий в настольные игры.
Дисциплина: Технологии разработки приложений на базе фреймворков.
ФИО, группу и вариант студент указывает самостоятельно.

### Цель

Настроить административную панель существующего проекта и расширить
работу с ORM, сохранив страницы и данные ПР9.

### Выполнение

Модели Game, Player и Match зарегистрированы в Django Admin.
Настроены русские названия, list_display, list_filter, search_fields,
ordering, list_per_page, date_hierarchy, autocomplete_fields.
В карточке игры показаны связанные партии: дату и длительность
можно редактировать через inline. В карточке партии редактируется состав
участников; сервер проверяет его количество и принадлежность победителя.
В карточке игрока отображается участие в партиях.
Массовые действия позволяют отменять, планировать и запускать партии.

Добавлено настоящее поле status с TextChoices: SCHEDULED, ACTIVE,
COMPLETED, CANCELLED. Миграция matches/0003_pr10_status преобразует
прежние is_completed и is_scheduled в status, сохраняя победителей.
Старые флаги оставлены для совместимости ПР9; они не редактируются,
синхронизируются с status и защищены ограничением согласованности.
QuerySet содержит active(), scheduled(), completed(), cancelled(),
for_date() и blocking(); эти методы используются в представлениях.

Список партий получает словари через values(), annotate(), F() и Count().
Сохранены фильтры и пагинация, добавлены фильтры по игроку и точной дате.
В статистике отображаются четыре счетчика статусов.
Подробная страница загружает игру и победителя через select_related(),
участников — через prefetch_related().

Добавлены slug игр и get_absolute_url(), прежние URL по ID сохранены.
Существующие игры получают game-ID, новые — слаг из названия
с транслитерацией и обработкой совпадений. Изменение названия не
меняет уже заполненный слаг.
GeneratedField is_large_group вычисляется базой: max_players >= 5.
Контекстный процессор передает название сайта и число игр в общий шаблон.

На странице /games/available/ реализована доступность на выбранный день.
Для учебного сценария предполагается один экземпляр каждой игры:
ACTIVE и SCHEDULED занимают ее, CANCELLED и COMPLETED — нет.
Это справочная проверка доступности; автоматического запрета на создание
двух партий одной игры на дату не заявляется.

Django Debug Toolbar подключен для локальной разработки и исключен
из тестов. Панель показывает SQL реальных страниц, JOIN, COUNT и
ограниченную выборку текущей страницы.

### Проверка

84 автоматизированных теста пройдены. Проверены админ-формы, inline,
массовая отмена, корректность победителя и состава, миграция статусов,
доступность, slug, GeneratedField, контекст и сохранение сценариев ПР9.
manage.py check и flake8 завершились без ошибок;
makemigrations --check --dry-run не обнаружил изменений.
Миграция проверяется на копии актуальной базы до применения к рабочей.
